# @gamut-plane/render

Private framework-neutral rendering support for the Vue and React instruments. It owns Canvas field painting, sampled gamut-guide tables, contour and interval geometry, and deterministic CSS/SVG presentation. Core owns color science; UI owns product copy and request policy; adapters own lifecycle, measurement, scheduling, and DOM. Applications import an adapter and its stylesheet rather than this package directly.

The sampled tables are approximate visual guides; in the instrument they back the Hue and Lightness slider intervals. Render's `perceptualGuides.ts` traces OKLCH L/C and OKLab a/b boundaries using core's numerical chroma-ray crossings. Render owns tolerance, topology assembly, bounded work and a four-slot memo that returns caller-owned buffers. Under the [approved Phase 2O contract](../../docs/phase-2o-field-viewport-spec.md#161-contract), each permanent acceptance fixture must measure <=1 CSS px at 8x on a 480 px field in both sampled directions, including Float32 and actual SVG serialization. This covers the built-in gamuts and nominal perceptual domains; it supplies no continuous or exhaustive component/topology certificate. The [independent oracle protocol](../../docs/testing.md#perceptual-guide-acceptance-protocol) states finite-sampling and engine limitations. Reference endpoints and Chroma intervals use the same numerical crossings; spatial Reference is unavailable when its requested contour fails. No guide determines exact gamut status or reauthors color. `pnpm --filter @gamut-plane/render check:gamut-tables` verifies the checked-in tables and digest. A hue-less observation remains null while visual sampling may use a zero-Hue slice.

The unsupported `@gamut-plane/render/internal/capabilities` entry resolves editor visual support, selected fields, and requested guide forms independently. A missing field relation, failed conversion, out-of-domain marker, and unsupported guide form retain distinct outcomes. Requested guide resolution is independent of exact checks and performs no hidden analysis.

The unsupported `@gamut-plane/render/internal/current` entry contains current-product integration: `currentField`, `currentOklchObservation`, `currentEditableDetail`, `generalizedGuideDisplay`, `generalizedEditableDetail`, and `referenceDisplay`, plus `planeWarningOffset` and `rangeWarningStyle` for shared annotation placement. These consume accepted owner-native facts and produce CSS, gradients, marker placement, and displayable guide geometry. They do not own public selection, target state, copy, or a second exact analysis. Native RGB editable detail uses the selected observation directly; its opaque fields and gradients keep actual encoded coordinates without OKLCH conversion.

Field and renderer cache keys include geometry/sampler identity, actual fixed coordinate, dimensions, DPR, granted Canvas space and quality. All six native RGB Areas have explicit support, independently of product admission and guide support. RGB boundaries use analytic linear-cube intersections and bounded encoded-curve approximation; full/empty/degenerate results remain successful independently of visible geometry. Native scalar intervals resolve independently. RGB Reference uses the nearest visible point on the native slice contour, with the same fixed channel and contour approximation bound; it does not depend on an OKLCH reference conversion. See [numerics, budgets and ownership](../../docs/native-rgb-guides.md). Renderer resources remain instance-local, allocated after mount, and import safely in Node. Packed consumer checks verify the private exports and declarations.

`referenceGuidePolicy` in `capabilities/guideSupport.ts` explicitly maps each supported Reference gamut to its primary spatial guide. `referenceDisplay` consumes only requested guide forms: perceptual sampled References or native RGB slice contours. It never fabricates a viewport edge or falls back to another gamut. Product Reference admission remains in UI.
