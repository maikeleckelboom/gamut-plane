# Testing

Use the pinned Node.js 24+ and pnpm 11.9.0. Install with `pnpm install --frozen-lockfile`. For browser suites, install the pinned Chromium with `pnpm --filter @gamut-plane/web exec playwright install chromium`; on Linux add `--with-deps`. Browser and packed suites start local servers on ports 4177–4182, so run them sequentially.

## Local workflow

During implementation, build affected packages and run the narrowest relevant test or typecheck. After the tree converges, build packages once, then use no-rebuild checks:

```powershell
pnpm format:check
pnpm lint
pnpm build:packages
pnpm typecheck:built
pnpm test:unit:built
pnpm --filter @gamut-plane/web build
pnpm check:build
pnpm test:e2e
pnpm test:production
pnpm test:package:built
pnpm test:react-vite:built
pnpm test:nuxt:built
pnpm test:next:built
```

`pnpm verify:prepush` runs formatting, lint, one package build, typechecking, unit/component tests, web build, and artifact inspection. It does not replace the browser, packed host, or SSR checks. Convenience commands without `:built` build packages first for an isolated run. CI builds packages once per job, then invokes built variants. It does not share build artifacts across jobs.

`pnpm --filter @gamut-plane/core typecheck:domain-nodom` and `test:packed-domain` protect the DOM-free core entry and packed declarations. `pnpm check:gamut-tables` verifies generated sampled data. The [release runbook](release.md) contains any extra release-specific requirements.

## Perceptual guide acceptance protocol

Run `pnpm --filter @gamut-plane/render exec vitest run test/perceptualGuides.test.ts test/tracedGuides.test.ts` after building core. It also runs through ordinary render tests and `pnpm verify:prepush`; no certification prototype or optional research command is required. A 120-second per-matrix-row timeout accommodates slower CI machines without changing the numerical threshold. Set `GAMUT_PLANE_ACCEPTANCE_EVIDENCE` to an existing ignored absolute directory to retain four JSON records with measured maxima, sample counts and observational trace timings. Timing values are not gates or isolated performance benchmarks.

`test/perceptualOracle.ts` specifies fixtures independently of production seeds, signatures, refinement and contour vertices:

- L/C hues: 106–113 by 0.25 degrees (yellow), 260–272 by 0.25 degrees (blue), plus 0, 29.2, 60, 90, 100, 118, 142.5, 180, 200, 258, 300, 328, 359.9, 264.1 and 264.125; duplicates are removed. Both gamuts use the same set.
- a/b lightnesses: 0.40–0.50 by 0.005, plus 0.0001, 0.001, 0.01, 0.04, 0.11, 0.2, 0.6, 0.9, 0.966, 0.97, 0.995, 0.999, 0.9999 and 0.4775, for both gamuts.
- L/C boundary queries: L=0.002–0.998 by 0.002, extra near-white rows 0.9505–0.9995 by 0.0005, and 0.0001, 0.0005, 0.001, 0.003, 0.006, 0.999, 0.9995, 0.9999. a/b queries use hues 0–359.9 by 0.1 degrees.

The boundary-to-contour oracle scans direct pinned `@texel/color` OKLCH-to-linear-RGB membership with zero tolerance, chroma step 0.0005 through 0.5, and 52 bisections at each observed membership transition. Near black (L<0.01), the scan spans 0–2L with step 0.0005L to retain resolution in the shrinking slice; this finite search envelope is itself an oracle limitation. Only crossings in C<=0.4 enter the nominal rectangle/disc metric. Each crossing is compared to the nearest geometric segment in both raw Float32 and parsed actual `geometryToSvgPath()` output. Neither oracle calls production ray crossings or contour assembly/refinement.

The contour-to-boundary oracle samples every segment's endpoints, quarter, midpoint and three-quarter points in both output representations. Direct texel OKLab membership is searched along four fixed directions, the segment normal and a gray-directed ray. Searches span +/-2 CSS px at 480 px/8x, using a uniform 0.125 px grid plus logarithmic offsets down to 2 px / 2^20, then 40 bisections per observed transition. Candidate witnesses must lie in the nominal rectangle/disc; crossing a domain edge alone is never a membership transition. Canonical L/C black/white point witnesses are included, without connecting them along the gray axis. The minimum found Euclidean distance is a finite directional estimate; no qualifying nearby witness produces an explicit test failure. The gray-directed query resolves acute cusp wedges independently of production roots. The finite direction search can overestimate the nearest distance; it cannot certify a continuous supremum. All fixture maxima must be <=1 CSS px, with slice, representation and direction in the failure message. No extra serialization allowance is added to that threshold.

Known three-crossing sRGB notch rays at (L,h)=(0.44,264.1), (0.006,264.1), (0.006,264.125), (0.45,264.125), and adjacent one-crossing rays at (0.006,264) and (0.006,264.25), independently verify contour crossing count/order for both geometries, plus nearest Euclidean boundary-to-contour distance. Same-ray displacement is not used as normal distance near tangencies. Exact black/white point serialization, extended empty slices, near-endpoint real budget failure, finite inputs, duplicate vertices and memo ownership have separate checks. Matrix rows check exact repeatability after evicting the memo. This covers observed cusp, fold/tangent, multiple-crossing and degenerate behavior without claiming global topology.

The sRGB a/b row at L=0.9999 has a specifically asserted existing `approximation-budget` result, repeated after memo eviction. It has no successful contour and therefore no accuracy maximum. Every other matrix slice must succeed and meet both distance limits; no generalized skip or accepted unknown failure exists. Both gamuts also explicitly reject work at L=1e-13 and 1-1e-13. This documents near-endpoint unavailability within bounded work, rather than replacing it with coarse or partial geometry.

`tracedGuides.test.ts` also feeds synthetic persistent disconnected branches through the actual production assemblers, asserting `numerical-failure` for an unvisited a/b loop and multiple L/C main chains. This directly guards detected incomplete traversal; it does not show that finite production seeds discover every real component. Resolution checks separately suppress stale contours and spatial Reference for both failure reasons, then recover without changing exact Outside.

Finite chroma/parameter/directional sampling can miss an arbitrarily narrow interval, tangency or separate component. The oracle shares the pinned conversion library and color model with core, while using independent membership searches rather than its numerical crossing solver. It does not verify colorimetric constants, exact roots, continuous Hausdorff distance, exhaustive components, all engines, crop-endpoint equivalence, stroke pixels or antialiasing. The supported nominal scope and strict production failure semantics remain in [spec §16](phase-2o-field-viewport-spec.md#161-contract).

## Packed consumers and production

Each packed runner builds tarballs, installs unpublished dependencies from those tarballs outside workspace resolution, verifies exports/declarations and installation contents, then builds or runs the host. `GAMUT_PLANE_EVIDENCE` retains browser/SSR evidence in CI. `--keep` retains a successful fixture for inspection. These checks do not prove registry installation.

`pnpm check:build` inspects the production app's file inventory, hashed assets, social image, and header policy. `pnpm test:production` serves `apps/web/dist` with the repository header rules and checks metadata, assets, generalized interaction, copy, and responsive behavior. Real Cloudflare routing/cache behavior remains a separate deployment check.

The [README screenshot](assets/gamut-plane-desktop.png), [social image](../apps/web/public/og/gamut-plane.png), and favicon are release assets. Generate them only when their actual presentation changes, inspect the result, and keep them separate from routine screenshot baseline updates. The 2M.4 exploratory Noble check found working pointer menus and Popover in Chromium, Firefox and WebKit. Playwright keyboard input emitted `contextmenu` only in Chromium; Firefox/WebKit emitted none on either the plane or an ordinary button, so their native keyboard invocation remains unverified. This is not a permanent cross-browser matrix. Physical devices and manual screen-reader use also require separate verification.
