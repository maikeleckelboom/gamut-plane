# TypeScript module and compiler policy

## Source and package modules

Keep relative `.js` specifiers in authored TypeScript, including references to `.tsx` modules. TypeScript resolves these to the source files during authoring; the NodeNext builds emit unbundled `.js` modules and `.d.ts` references with the same distributable identities. Vue uses Vite for JavaScript and `vue-tsc` for declarations. This convention makes native Node ESM, declarations, and packed packages agree without a loader, alias map, or declaration repair step.

The Tooling T1 inventory found **351** relative `.js` specifiers in TypeScript-authored files: 328 target `.ts`, 23 target `.tsx`, and none target authored `.js`. The counts include imports, type imports, re-exports, export-star, and import types across `apps/`, `packages/`, and `scripts/`; there were no relative dynamic `.js` imports. Counts remain unchanged. No custom source checker was added: NodeNext builds, package tests, and strict packed declaration consumers exercise the invariant.

The B spike covered `.ts → .ts`, `.ts → .tsx`, `.tsx → .ts`, `.tsx → .tsx`, type imports, re-exports, export-star, and dynamic imports. For example, source `export * from "./child.tsx"` became `export * from "./child.js"` in JavaScript but remained `export * from "./child.tsx"` in the declaration. A private import map can run under Node, yet the tested `types: src` / `default: dist` mapping made a source Vitest test use stale output. Neither option is neutral to the current package and IDE contract. Reconsider `.ts` source paths if a future compiler emits distributable `.js` declaration specifiers as well, or another native mechanism passes source, packed, IDE, and framework checks without extra mapping or processing.

## Effective compiler policy

The shared config applies to core, render, UI, React, Vue source/declarations, and Vue Node tooling. It keeps `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `isolatedModules`, and casing checks. It now also checks implicit returns and overrides, switch fallthrough, unused declarations/parameters, unreachable code, unused labels, forced module detection, and erasable syntax. Emitting builds inherit `noEmitOnError` so compiler errors cannot produce a fresh partial artifact. The web app and its separate Node config apply the corresponding checks explicitly; the web app's former exact-optional exception is removed.

| Candidate                                                                                         | T1 result                       | Reason                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `exactOptionalPropertyTypes`                                                                      | Enabled in source/build configs | Vue's broad `false` override and the web app's override were removed. Shared-policy inputs now omit absent fields; Vue props that already accept present `undefined` retain that behavior explicitly. Independent packed-consumer templates retain their host configs.                    |
| `skipLibCheck: false`                                                                             | Deferred globally               | Core/render/UI/React and Vue Node configs passed the experiment. Vue source and web app hit four missing Web Bluetooth names in `@vueuse/core`; web Node tooling hit Playwright DOM types outside its Node-only lib. Keep strict packed declaration consumers with `skipLibCheck: false`. |
| `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noImplicitOverride`, `moduleDetection: force` | Enabled                         | All workspace configurations passed the candidate experiment.                                                                                                                                                                                                                             |
| `noEmitOnError`                                                                                   | Enabled for emit builds         | Inherited from the shared config by tsc and Vue declaration builds.                                                                                                                                                                                                                       |
| `noUnusedLocals`, `noUnusedParameters`                                                            | Enabled                         | Current source, tests, and Node scripts passed without fixture exceptions.                                                                                                                                                                                                                |
| `noPropertyAccessFromIndexSignature`                                                              | Deferred                        | The experiment reported broad mechanical changes to intentional dictionaries (for example color-channel records, attribute names, and environment maps) without exposing an incorrect assumption.                                                                                         |
| `noUncheckedSideEffectImports`                                                                    | Deferred                        | Vite's `*.css` ambient module accepts even nonexistent CSS paths, so enabling the flag would not meet the typo-detection requirement for the application's side-effect styles.                                                                                                            |

Oxlint's supported `typescript/no-explicit-any` rule applies to production source. Test-only impossible-state fixtures remain outside that override. No production `any`, double assertion, or `@ts-ignore` was introduced.

## Validation

Use `pnpm typecheck`, `pnpm build`, `pnpm check:build`, `pnpm test`, the package's packed-consumer commands, and `pnpm test:e2e` / `pnpm test:production` for the current convention. `pnpm test:package`, `pnpm test:react-vite`, `pnpm test:nuxt`, and `pnpm test:next` exercise freshly packed framework consumers. Core's `typecheck:domain-nodom` and `test:packed-domain` protect its Node-only domain boundary. The Vue and React packed Vite consumers compile declarations with `skipLibCheck: false`; NodeNext packed checks complement those Bundler-mode hosts. These automatic artifact checks are an IDE-quality proxy, not a manual PhpStorm test.
