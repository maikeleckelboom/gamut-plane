# Gamut Plane v0.3.0 — release and migration notes

This is the release candidate for the public application/repository version `v0.3.0`. The four reusable private tarball versions are `0.2.0`. They remain `private: true` and unpublished to npm; after release, consumers can obtain the tarballs and `SHA256SUMS` from GitHub release assets.

## What changed

- `ColorValue` is the one selected, authored color. Its defining representation may be OKLCH, OKLab, sRGB, or Display P3; it is not always OKLCH.
- `definitionOf` reads authorship and `represent` observes another space without changing it. Switching the OKLCH/OKLab view only observes; an actual edit creates a new `ColorValue` defined in that plane.
- A hue-less OKLCH neutral keeps `h: null`; a numeric hue is established by a real Hue edit. A numeric field hue used to draw the plane is presentation data.
- `analyzeGamut(original ColorValue)` owns exact `inside | within-tolerance | outside` status. Contours, channel intervals, and the target guide are sampled visual references, never exact status or a replacement selected color.
- `mapToGamut` is the only mapping operation. Strict `serializeCss` and `serializeHex` output is explicit and can reject out-of-gamut or tolerance-fringe values; no hidden clamp or mapping occurs.
- `snapshotColor` and `restoreColor` cross JSON, SSR, and other serialization boundaries. Do not serialize a live `ColorValue` as ordinary component props.
- The Hue strip previews the selected Lightness and Chroma. Dragging beyond its right edge keeps the thumb at 360 while the authored hue correctly wraps to 0.
- The renderer's sampled tables, field buffers, invalidation paths, and Hue preview remain intact. Packed Vue/Nuxt and React/Vite/Next consumers prove ordinary SSR, hydration, and React root Strict Mode behavior.

This is a breaking consumer-contract release after application v0.2.1: selected-color authority, adapter props/models, and core input/output APIs changed. The application moves to the next minor version while the private packages move together from 0.1.0 to 0.2.0.

## Breaking component migration

**Before:** a selected `OklchColor` value was treated as the authority for both views.

**Now:** hold a `ColorValue`; construct it from a defining representation and let a real edit re-author it in the edited plane. Ordinary extended and out-of-display-gamut values remain authored. The instrument requires numerical representability in both OKLCH and OKLab views; pathological finite core values may return `numerical-range` during observation or projection and are not silently replaced.

Vue:

```vue
<script setup lang="ts">
import { ref } from "vue";
import { createColorValue } from "@gamut-plane/core";
import { GamutPlane, type ColorValue } from "@gamut-plane/vue";
import "@gamut-plane/vue/style.css";

const initial = createColorValue({ space: "oklch", channels: [0.68, 0.18, 252], alpha: 1 });
if (!initial.ok) throw new Error("Invalid initial color");
const color = ref<ColorValue>(initial.value);
</script>

<template>
  <GamutPlane v-model="color" />
</template>
```

React:

```tsx
import { useState } from "react";
import { createColorValue } from "@gamut-plane/core";
import { GamutPlane, type ColorValue } from "@gamut-plane/react";
import "@gamut-plane/react/style.css";

const initial = createColorValue({ space: "oklch", channels: [0.68, 0.18, 252], alpha: 1 });
if (!initial.ok) throw new Error("Invalid initial color");

function Editor() {
  const [color, setColor] = useState<ColorValue>(initial.value);
  return <GamutPlane value={color} onValueChange={setColor} />;
}
```

For both adapters, choose the view independently from the selected value. Vue uses `v-model:plane`; React uses `view`/`onViewChange` or `defaultView`. Update any code that inferred authored space from the current view.

## Old core API replacements

| Earlier consumer use                     | v0.3.0 contract                                      |
| ---------------------------------------- | ---------------------------------------------------- |
| Selected `OklchColor`                    | `ColorValue` with a defining `ColorRepresentation`   |
| `parseCssColor`                          | `parseCssValue`                                      |
| `isColorInGamut`                         | `analyzeGamut` and its three-state status            |
| `serializeColor`                         | `serializeCss` with an explicit output policy        |
| `serializeHexColor`                      | `serializeHex` with an explicit alpha option         |
| `toOklabColor` / `toOklchColor`          | `represent` for observation                          |
| Implicit display-gamut clipping          | Explicit `mapToGamut` when lossy mapping is intended |
| Plain object transport of selected color | `snapshotColor` / `restoreColor`                     |

The package tarballs are `gamut-plane-core-0.2.0.tgz`, `gamut-plane-render-0.2.0.tgz`, `gamut-plane-vue-0.2.0.tgz`, and `gamut-plane-react-0.2.0.tgz`. Install the matching core/render artifacts with either adapter, using the [local-install guidance](../../README.md#install-local-packages). Registry publication is disabled.
